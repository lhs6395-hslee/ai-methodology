Ownership Key — 역할 기반 5분류

스펙 간 기능 중복을 예외 없이 막기 위한 소유권 키 모델. 이름이 아니라 역할(role)로 판정하고, 역할마다 실재·귀속 불변식을 강제한다. (SDD 방법론 감사 #21 반영 — 정본: DEDUP.md §3.5)

1왜 역할(role)인가

각 스펙은 ## Ownership에 자신만 소유한 키를 선언한다. 한 키는 정확히 한 스펙 — 둘이 같은 키를 소유하면 구조적 중복(결정적 게이트가 exit 1).

과거엔 판정이 카테고리 이름(/entit/ 정규식)에 걸려 있어, 이름을 Entities→Aggregates로 바꾸는 한 줄이면 강제가 조용히 죽었다(감사 A-1). 이제는 config ownershipCategoryRoles로 역할을 선언하고 모든 판정이 그 역할에 걸린다 — 이름은 자유롭고(웹 Entities, 킷 Modules), 킷 자신도 규칙을 자기에게 적용한다(도그푸딩 공백 해소, SPEC-001 FR-010).

카테고리 이름(자유)→ ownershipCategoryRoles→ 역할(entity·surface·capability·engine·event)→ 역할별 불변식 강제

2다섯 역할과 불변식

모든 소유 키는 무슨 역할인지 + 그 역할의 SSOT로 뒷받침되는지가 강제된다.

entity — aggregate root

키: 스키마 식별자 그대로 (예: pjt_projects)
구조 SSOT(스키마·마이그레이션)에 실재 + entityRegistry 등록 + 스펙당 최소 1개(entity 없는 번들 금지) + maxAggregateRootsPerSpec 이하.
SPEC-026 스키마 백킹 · SPEC-002 입도 하한/상한

surface — route·화면

키: <METHOD> <path> (예: POST /api/pjt)
파일형 심볼은 소스 루트에 정방향 실재(orphan 역방향 판정의 짝).
SPEC-029 심볼 실재

capability

키: entity.verb (예: pjt_projects.create)
verb의 entity 조각을 그 스펙이 소유해야 함(귀속). cohesion 캡은 entity별로 카운트 — full-CRUD가 거짓 분할 신호를 받지 않게.
SPEC-024 귀속 · SPEC-002 entity별 캡

engine — 순수 로직 (신규)

키: 모듈 식별자 (예: priceRules)
코드-모듈 SSOT(enginesSources)에 실재. capability 소유 금지(능력은 entity에 귀속).
SPEC-030 (옵트인)

event — 신호·job (신규)

키: entity.event-name (예: order.created)
발신 entity에 귀속 + 이벤트 카탈로그(eventCatalogSources)에 실재. job:를 무검증 Surface로 개명하던 우회를 봉합.
SPEC-030 (옵트인)

engine·event는 옵트인(역할 선언 전용·이름 폴백 없음) — 미선언 프로젝트는 무영향. 참조(읽기/호출만)하는 남의 entity는 ## Dependencies에 EntityName (relation-type)로 두어 dedup에서 제외한다(SPEC-017).

3"중복·과분류·예외 없이"의 실제 장치

목표담당 장치한계
중복 없이 dedup 키 유일성(역할·카테고리 내, check-ownership) 의미적(동의어 order/orders) 중복은 확률적 리뷰 몫
과분류 없이 실재 불변식(스키마·심볼·모듈·카탈로그)이 유령·억지 분류 차단 + engine/event가 전수성 구멍을 담음 다부모 개념은 relation 참조로 표현(단일 트리로 접지 않음)
예외 없이 강도 knob 하향 불가(단조 증가, SPEC-027 래칫 — 자기 포함). 면제는 사유 필수 + 매 실행 부채 표면화 hard 전면화 속도는 프로젝트별 graduation
예외 없이 = 하향 불가. 위반이 대량으로 떠도 정책 강도를 hard→advisory로 내려 회피할 수 없다. off·advisory는 마이그레이션 중 경유지일 뿐 종착지는 hard. 신규 채택은 hard로 태어나되, 기존 프로젝트의 소급 범람만 graduation으로 완충한다(범람 회피가 목적이지 예외가 아님).
정직한 잔여 한계. ① 말만 바꾼(reworded) 의미적 중복은 결정적 게이트로 못 잡는다 — 같은 entity 이웃 스펙 좁힌 리뷰(## Dedup-Review)로 보조. ② 다부모(한 개념이 두 aggregate 소속)는 relation 참조. ③ hard 전면 강제는 채택 속도에 달려 있다.
